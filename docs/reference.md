# Catalog Workshop reference

Detailed reference for engineers: folders, scripts, checks, expression builtins, lookup files, template/customer keys, web UI and API. The short working guide is `CLAUDE.md`; decision history is `docs/audit-decisions.md`.

## Status (as of 2026-10-02: all 111 templates clean, all 236 customers match their real file exactly — known gaps copied into `real_cell_snapshot.csv`)

Local sandbox only (no AWS/production access), mirroring the production "Generic Catalog Export" pipeline (STEP → SQS → Lambda → S3, see pim-docs). Full history: [`docs/audit-decisions.md`](docs/audit-decisions.md) (per-template audits, generator mechanisms, original text of condensed sections); per-customer status: [`docs/baseline-reconciliation.md`](docs/baseline-reconciliation.md).

### Folder structure
- `master/products.csv` — canonical product data, 26,130 SKUs from the 2026-09-02 CST export (`incoming/cst_data.csv`) via `scripts/import_master_data.py`. `master/products_neb.csv` = NEB rows; other `master/*.csv` = `lookup()` tables. `incoming/cst_data_2.csv` = richer 112-column raw export.
- `config/templates/{name}.json` — one per catalog format (first ones from the 6 sample files): `columns` (header + Python expression over `row`/`discount`/`customer`/`price_period`), `sku_column`, `price_columns`, optional keys below.
- `config/customers/{slug}.json` — `template_ref`, `discount_percentage`, `price_valid_from`/`until`, `file_type`, `overrides`, optional `price_period`; Future siblings use a `-future` slug.
- `catalogs/{slug}/` — generated output, one folder per customer. **Not tracked in git** (since 2026-09-25): catalogs are rebuildable from config + master, and the audit log records every generate. A rolling history is kept: after a successful write, `prune_older_catalogs()` keeps the newest `CATALOG_HISTORY_KEEP` files (default 12, env override; one per generate day, since a same-day regenerate overwrites that day's file; up to ~12 GB) and lists deleted names under `detail.pruned` in that generate's audit entry. 2026-10-02: a one-time cleanup first kept only the newest file (470 files removed, audited as `prune_catalogs`); changed to the rolling history the same day after the business-user workflow tests showed "what changed since last month?" needs older versions. `scripts/compare_versions.py <slug> [--from DATE] [--to DATE] [--list] [--out changes.csv]` diffs two kept versions in business terms (products added/removed, columns added/removed, per-column changes, price moves vs format-only, cell types) and lists that customer's audit entries and config/template commits in between.
- `audit/{date}.jsonl` — append-only who/what/when/outcome, success and failure. `CATALOG_AUDIT_DIR` overrides the folder (generator, scoreboard, importers, web UI) — parallel agents in git worktrees set it to the main checkout's `audit/` so entries land in one log with no manual merge. `timestamp` is local time with an explicit UTC offset (`audit_timestamp()`, since 2026-09-26; earlier entries are UTC `+00:00`) — always compare as datetimes, never as strings. The daily file name and catalog filename dates are still UTC dates. Actions `generate_catalog`, `update_customer_config` / `create_customer` (web UI and `scripts/customer_config.py`, detail `{field: {old, new}}`), `import_master_data`, `fidelity_scoreboard`, `retire_snapshot_rows`, `prune_catalogs`. `source` = `business` (done for a business user: `customer_config.py`, web UI edits/Generate, `generate_catalog.py <one slug>`) or `engineering` (`all` runs, scoreboard, imports, cleanup); `--source`/`CATALOG_AUDIT_SOURCE` override; entries before 2026-10-02 are classified on read by `audit_source()` (config changes business, the rest engineering). `customer_config.py history`, `compare_versions.py` and the web UI Audit Log (`GET /audit?source=`) list business changes and count engineering runs. `detail` = `{"rows_written": N, "warnings": [...]}` or `{"errors": [...], "warnings": [...]}`; pre-2026-09-01 entries have a plain string Since 2026-09-26 `append_audit` caps `errors`/`warnings` at the first 20 (`cap_messages_for_audit`) and adds `errors_total` + `errors_by_pattern` (count per message with the row prefix stripped) when truncated; callers still get the full list. (Five failed generates on 2026-09-18 logged every row, which is why that file is 68 MB; left as is.)
- `scripts/generate_catalog.py` — generator, importable (`scripts/__init__.py`). `python3 scripts/generate_catalog.py <customer-slug|all> [--requested-by X] [--request "..."] [--dry-run]`. With `all`, a customer whose generate raises (e.g. an expression error, which is a `SystemExit`) is printed as `ERROR`, audited as `failed` and skipped; the run continues and exits 1 (since 2026-10-02; the web UI regenerate job also catches `SystemExit` now).
- `scripts/import_neb_brand_data.py <input.pkl> [--requested-by X] [--dry-run]` — builds `master/products_neb.csv` (New England Biolabs products distributed through the Benelux pipeline; same 19-column shape as `products.csv`, no SKU overlap with CST).
- `scripts/import_master_data.py <path.csv> [--requested-by X] [--dry-run]` — maps a raw CST export onto master and overwrites it (export mislabels: `gbp` = USD price when `CURRENCYCODE` is USD; `Image_URL_US` = product page, `primary_image_url` = image). Regenerate catalogs afterward.
- `scripts/customer_config.py show|history|set|create|exclude|include` (added 2026-10-02) — audited config changes from the CLI, for business-user requests: `set <slug> --discount/--valid-from/--valid-until`, `create <new> --like <existing> --display-name ...` (drops the source's `customer_id`/`step_classification_id`/notes, maps the new slug to `null` in `fidelity_file_map.json`), `exclude/include <slug> SKU... --reason` (the customer's OWN list `config/exclusions/<slug>.csv`, read automatically by `prepare_rows()` on top of any shared `overrides.excluded_skus_lookup`, which may now also be a list of files), `--with-future` applies to the sibling, `--dry-run`, `--requested-by`/`--request`. Validates discount 0–100 and from < until; edits keep the file's formatting. Audit: `update_customer_config` / `create_customer` with `{field: {old, new}}` (the web UI PATCH records old/new too since 2026-10-02); `history` lists those plus the config file's commits. Never edit a shared exclusion list for one customer: `show` prints how many customers share it (Coupa UK's: 30).
- `scripts/retire_snapshot_rows.py [--dry-run] [--workers 2] [--drop-orphans]` (added 2026-10-02) — after a fresh CST export/master import: rebuilds every customer that has `real_cell_snapshot.csv` rows with the snapshot switched off (`generate_catalog.SNAPSHOT_DISABLED`) and retires each row whose column's own fallback expression now writes exactly the real cell (value, and number-vs-text for xlsx) for every customer sharing that `display_name`; anything uncertain is kept. Records the master fingerprint (sha256 of `master/*.csv` minus the snapshot) in `master/real_cell_snapshot.meta.json` and writes a `retire_snapshot_rows` audit entry. The generator's `snapshot_review` warning (`check_snapshot_review`, customers with snapshot cells only) fires whenever `master/*.csv` no longer matches that fingerprint. Flow: import → rebuild lookups → retire → full refresh.
- `scripts/compare_catalog.py <real> <generated> [--sku COL]` (the scoreboard also passes the template's `sheet_name`, compared when both workbooks have that sheet) — audit tool: full-population header order, row population, value + cell type (xlsx `data_only=False`), CSV byte framing. Use it for every template audit.
- `scripts/fidelity_scoreboard.py [all|<slug>...|--template T] [--workers 3] [--from-catalogs]` (`--template` runs are partial, never touch `latest.*`) — regenerates into a temp dir (no catalogs written, no quality checks); `--from-catalogs` instead compares each customer's newest `catalogs/` file when it's newer than its customer config, template, every `master/*.csv` and `generate_catalog.py` (stale or missing → regenerated, flagged in the progress line; result carries `generated_from`). Full refresh = `generate_catalog.py all` then `fidelity_scoreboard.py all --from-catalogs`, which skips building every catalog twice; any edit to `generate_catalog.py` makes every catalog stale for this check and compares every customer against its real file; labels each diff `coverage_gap` (SKU absent from `cst_data_2.csv`) / `rounding` / `number_format` / `whitespace` / `other`. Writes `reports/fidelity/<ts>.{json,md}` (on disk, not tracked; the newest 30 are kept, `prune_reports()`); full runs also update `latest.*` (tracked; the web UI reads it) with changes since the previous run. One `fidelity_scoreboard` audit entry per run. Real file = `display_name` match (suffixes like `(3)` ignored) or `config/fidelity_file_map.json` (null = no real file). Documented, unfixable residuals live in `config/fidelity_accepted.json` (exact template + column + SKUs, with reason and doc pointer) and are labelled `accepted`. Every template is bucketed **clean** (all customers match or differ only by coverage gaps/accepted residuals) or **needs_work** (anything else, incl. no real file).
- `webapp/` — web UI (below).

### Quality checks (in `generate_catalog.py`)
Blocking (failed check → nothing written, `outcome: "failed"` audit entry):
- **Config sanity** (`check_config_sanity`): `sku_column`/`price_columns` must be declared columns
- **Master data integrity** (`check_master_data`, once per run): no blank/duplicate `sku`; no blank `short_description`; `list_price_usd` numeric > 0; `unspsc` 8 digits and `cas_number` CAS format when present
- **Discount ranges**: `discount_percentage`, `category_discounts`, `institutions.*.discount_percentage` in [0, 100]
- **Price validity window**: `price_valid_from` < `price_valid_until`
- **Output SKUs**: no blank/duplicate `sku_column` values
- **Price columns**: no negative/non-numeric `price_columns` values (blanks skipped, `price_prefix` stripped, `decimal_comma` honored)
- **Price relationships** (`check_price_relationships`): `Price 1/2/3` non-increasing; `Discounted Price` ≤ `List Price`; implied discount matches a configured one
- **Required fields** (`check_required_fields`): no blank "description" column (opt-out `allow_blank_description`)

Warnings (non-blocking):
- **Snapshot review** (`check_snapshot_review`, 2026-10-02): `master/*.csv` changed since `retire_snapshot_rows.py` last reviewed `real_cell_snapshot.csv` (fingerprint in `real_cell_snapshot.meta.json`); copied cells may be stale or reproducible
- **Override coverage** (`check_override_coverage`): SKU-keyed override (e.g. `overrides.regional_prices`) misses rows
- **Row-count regression** (`check_row_count_regression`): ≥10% swing vs. last generated catalog (re-parsed with the template's `delimiter`/`csv_format`, BOM-aware)
- **Category discount distribution** (`check_category_discount_distribution`): rows per `category_discounts` bucket, from realized prices
- **Cross-period consistency** (`check_cross_period_consistency`): for `-future` pairs (e.g. `bayer-de`/`bayer-de-future`), checked from both sides since 2026-10-02 (a Future-only change used to pass silently), config drift only — `template_ref`/`file_type`, discounts, overlapping validity windows, `display_name`. Expected warnings: Future files that revert to 0% (`de-helf-future`, `eu-imba-future`, `eu-oms-future`, the four sap-gdsn Futures, `evotec-future`, `boehringer-pharma-germany-future`, `amici-future`, `charite-future`, `max-planck-future`, …; verified vs `incoming/Catalogs/Future Price/` — 2026-09-26 sweep checked every customer's price columns against its real file) and `zageno-future`'s different real layout. History in `docs/audit-decisions.md`.

### Running parallel agents (worktrees)
- A worktree agent's branch can start on a stale commit: first step is `git reset --hard main` if `HEAD` is behind `main`.
- Symlink `incoming/` (gitignored) from the main checkout; never commit it.
- `export CATALOG_AUDIT_DIR="<main checkout>/audit"` so audit entries go straight to the main log; don't commit `audit/` from the worktree.
- 8 GB RAM: agents run the scoreboard with `--workers 1`, never `all`; split work by template group (not by pattern) so branches merge without conflicts.

### Decisions & known limitations

**Real-file snapshots (POC):** when no available source reproduces a real column, copying it from the real file into a documented `master/*_snapshot.csv` lookup is acceptable in this sandbox (user decision 2026-09-25) - label it as copied, keep a fallback to the best real source, and note it's frozen. **Standing directive:** replicate each real source file exactly, quirks included (stale discount labels, header/content mismatches, `00AE` garbled entities, inconsistent formatting); verify against `incoming/` before "fixing" any diff. Never fabricate: blank only when confirmed 100% blank in the real file (`allow_blank_description` if needed); document unexplained residuals rather than inferring values.

**Audit checklist:**
- Profile the full population of both Current and Future files — never sample.
- Compare value AND cell type: real `.xlsx` prices/constants are often TEXT (`'415.00'`, `'1'`); bare `round(x,2)`/ints write number cells.
- Compare the full header list in order — dropped always-blank columns shift positions.
- Read `.xlsx` with openpyxl `data_only=False`: uncached `=HYPERLINK()` formula columns look blank otherwise.
- Byte-compare CSV/TXT (`cmp`): line endings, BOM, leading blank line, header row, `ENDOFDATA`, delimiter — field diffs hide these.
- Diff row populations; reuse an exclusion lookup only if byte-identical, not just same count.
- Verify Current and Future discounts independently (Future often reverts to 0% with a stale label — use a `price_period` check in the expression).
- Check `incoming/cst_data_2.csv` before calling a column "no source".
- Whole-number price strings (`'614'`) come from raw `cst_data_2.csv` fields: use `cst_uk_clp.csv` (GBP) / `cst_dkfz_bmecat_fields.csv` (EUR).
- A template's own `description` or config `_note` can be wrong.
- Rounding mode is per-template (`price_for_rounded` half-even vs `_half_up`); naive float `round()` misses half-cents.
- `'µ'.upper()` → Greek `'Μ'`; handle `µ` explicitly (kept or transliterated to `u` per column).
- Test-count source is per-template: `cst_marketing_name_details.csv` `test_count_uni_abbrev` vs `cst_test_count.csv` (disagree, e.g. `74332T`).
- Master `manufacturer` is `'Cell Signaling Technology, Inc.'` and `uom` is `'Ea'`; real files almost never use them raw. Per column: `.rstrip('.')` (→ `, Inc`), `.replace(', Inc.', '')` (keeps NEB's `'New England Biolabs'`), or a constant; UOM `.upper()` (`EA`) or `.lower()` (`ea`, Ohio State). Check both columns of a pair (e.g. Supplier vs Manufacturer) separately.
- Same field can use different cleaning rules per column; shared templates can differ per customer (see `distributor-staggered`/`benelux-vwr-mel` splits).

**Expression builtins** (`EXPR_BUILTINS`, plus `round float int str len min max`):
| Name | Behavior |
|---|---|
| `price_for(row, field, customer)` | `field` or `field_future` per `price_period` |
| `price_for_rounded(row, field, customer, discount)` | Decimal, half-even, 2dp string (discount 0 → TEXT list price) |
| `price_for_rounded_half_up(...)` | Same, half-up |
| `price_text(value, discount=0, half_up=False)` | Same Decimal math on an explicit value (e.g. `row['list_price_eur']`, no `price_period` switch) → 2dp TEXT |
| `strip_trailing_zeros(s)` | `'415.00'`→`'415'` |
| `lookup(key, file, column, default="")` | `master/` CSV keyed by first column, cached |
| `sku_leading_digits` / alias `leading_digits` | `'64668S'`→`'64668'` |
| `chr` | Python `chr` (e.g. `chr(181)`=`µ`) |

### Web UI (added 2026-09-01)
FastAPI backend (`webapp/backend/main.py`) wraps `generate_catalog.py` (no duplicated logic) and serves the static frontend (`webapp/frontend/index.html`, no build step). Install `pip3 install -r webapp/backend/requirements.txt` (fastapi, uvicorn, openpyxl), run `PATH="$HOME/Library/Python/3.14/bin:$PATH" uvicorn webapp.backend.main:app --port 8000`, open `http://127.0.0.1:8000/`.

**Stale-code guard** (2026-10-02): the server records the mtimes of `generate_catalog.py`, `fidelity_scoreboard.py` and `webapp/backend/*.py` at startup; once any changes, Preview/Generate/pending-changes and regenerate/refresh jobs return 409 ("restart the web server") and every tab shows a banner (`GET /server/status` → `{started_at, stale_code}`). Scoreboard jobs (subprocess) are unaffected. Restart after any generator edit; no auto-reload, since it would kill a running job.

**No auth yet**: `requested_by` defaults to `$USER` (`_requested_by()`); must come from a verified server-side session before multi-user use.

- **Customers tab**: chip filters for Period (All/Current/Future), Region (multi-select US/DE/UK/EU/NL) and NEB only, each with a live count that reflects the other active filters, plus Clear filters; choices persist in localStorage. Rows show region/NEB/period pills; Current and Future siblings are listed next to each other. Status badge from the last audited generate (`Up to date`, `N warning(s)`, `Stale — regenerate` = row-count regression, `Last generate failed`, `Never generated`), plus a fidelity badge from `reports/fidelity/latest.json` (`Matches real file`, `Known gaps only`, `N wrong columns`, `Structural diffs`, `No real file`, `Not scored`) and a fidelity filter; the customer view has a "Fidelity vs. real file" section (structural issues, header/cell-type diffs, per-column cause breakdown with real-vs-generated examples). Edits only `discount_percentage`/`category_discounts`, `price_valid_from`/`until`, `overrides` (validated; refused values aren't saved); an "Excluded products" section lists/edits the customer's own exclusions and names shared lists with their user counts; Catalog history has "Compare with previous" per version; "Change history" lists business changes (old → new) and counts engineering runs; "New customer like this…" creates a copy; the fidelity section says how many cells are copied from the real file; Save and Exclude can also apply to the other price period (template expressions are `eval()`'d, so engineer-only), logged as `update_customer_config`. **Preview (dry run)** runs `generate()` directly. **Generate** instead opens a review panel first (`GET /customers/{slug}/pending-changes`): config edits since the last successful generate, a row-count delta (previous `rows_written` → a fresh dry run's row count), and that dry run's warnings/blocking errors; Confirm & Generate then runs the real generate (disabled if the dry run has blocking errors), Cancel discards the panel. Shown even with no changes/regression ("no changes and no row-count regression detected") — Confirm is still required. **Regenerate All Customers** starts a server-side `regenerate` job (see Background jobs); **Refresh Everything** starts a `refresh` job (regenerate all + fidelity scoreboard `--from-catalogs`, see Background jobs) and reloads customers + fidelity when it finishes; the customer view's **Re-check fidelity** starts a single-customer `scoreboard` job and shows that fresh result above the last full run, labelled with its report file/time (from `GET /fidelity/{slug}/recent`, since partial runs never update `latest.json`; list badges keep showing the last full run).
- **Master Data tab**: search/paginate `master/products.csv`, product detail, `master_row_flags` highlighting + "Flagged only", Export CSV.
- **Validations tab**: `CHECK_REGISTRY` inventory (8 blocking, 5 warning) with applicability per customer/template.
- **Fidelity tab**: templates from the last scoreboard run (report timestamp shown), ranked like `latest.md` (needs_work first, by wrong-column count), sortable by column, filterable by bucket/text; clicking a template lists its customers and their wrong columns (click through to the customer). **Run fidelity scoreboard** starts a full `scoreboard` job and reloads the tab when it finishes; the backend re-reads `latest.json` only when its mtime changes, 404 if missing.
- **Audit Log tab**: filter by customer/outcome/date range.
- **Background jobs** (`webapp/backend/jobs.py`, added 2026-09-26): in-process runner, **one job at a time** (a second start → 409; both are heavy on 8 GB), background thread. State (current job + last 20 finished) is persisted to `webapp/backend/jobs_state.json` (gitignored, rewritten atomically on every change). Jobs are **not resumed** after a restart: on startup a queued/running job becomes `interrupted` (`finished_at` set, error `server restarted`); an interrupted scoreboard gets the same `failed` `fidelity_scoreboard` audit entry as a cancel (unless it already wrote its report) and its orphaned subprocess group is terminated (pid + command line checked); an interrupted regenerate records `finished_slugs`/`not_run_slugs` (finished customers already have their own audit entries). Server shutdown also terminates a running scoreboard subprocess. `regenerate` calls `generate()` per customer (per-customer audit entries as usual; exceptions are audited as `failed`), records ok/blocked/error, rows, warning count; cancel stops after the current customer. `scoreboard` runs `scripts/fidelity_scoreboard.py <slugs|all> --requested-by <user> --request "web UI scoreboard job"` as a subprocess (own process group) and parses its `[i/N] slug: status` lines; cancel terminates it (then the job writes a `failed` `fidelity_scoreboard` audit entry, since the script didn't reach its own). `refresh` (added 2026-09-26) runs both phases as one job, all customers: phase 1 reuses `_run_regenerate` verbatim (same `items`/`summary`/`done`/`total` fields, one `generate_catalog` audit entry per customer as usual); phase 1's `items`/`summary` are then snapshotted into `phase1_items`/`phase1_summary` and reset to zero before phase 2 reuses the same scoreboard subprocess helper as `scoreboard` (`_run_scoreboard_subprocess`, request text `"web UI refresh job"`) with `--from-catalogs` so it doesn't rebuild every catalog a second time; only a full scoreboard-with-report updates `latest.json`, same as a plain `scoreboard` job. The job's `phase` (1 or 2) and `phase_count` (2) drive the UI's phase-aware progress line (e.g. "1/2 Regenerate 45/236", then "2/2 Scoreboard …"). Cancel during phase 1 stops after the current customer and skips phase 2 entirely (`phase` stays 1, an error notes phase 2 was skipped); cancel during phase 2 terminates the scoreboard subprocess exactly like a plain `scoreboard` cancel. An interrupt at restart is handled the same way: phase 1 gets the regenerate-style `finished_slugs`/`not_run_slugs` treatment, phase 2 gets the scoreboard-style orphan-subprocess-termination + `failed` audit entry. Timestamps via `audit_timestamp()`. A progress panel (done/total, current item, elapsed, ETA, Cancel, then a summary) shows on every tab; the page polls `GET /jobs` every 2 s and reattaches on load, so closing/reloading the tab never stops a job. On load, if the newest job finished and this browser never saw its summary, the summary is shown once ("seen" job ids in `localStorage`, per browser). While a job runs, a real per-customer **Generate** is refused (`POST /customers/{slug}/generate` → 409, button disabled with a note); **Preview (dry run)** still works.
